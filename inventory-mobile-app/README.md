# Inventory Manager — Mobile App (Capacitor wrapper)

This wraps your existing `frontend/` (unchanged HTML/CSS/JS) into an installable
Android app. No rewrite — same login page, same dashboard, same JS calling the
same REST API.

Everything here has already been generated and tested up through project scaffolding
(`npm install`, `cap init`, `cap add android`, `cap sync` all ran successfully). The
one step that needs your own machine is the final native build, because that
requires Android Studio / the Android SDK, which isn't available in this environment.

---

## 1. What's in this folder

```
inventory-mobile-app/
├── www/                     # your frontend, copied in as-is
│   ├── index.html
│   ├── dashboard.html
│   ├── css/style.css
│   └── js/{api.js, login.js, dashboard.js}
├── android/                 # native Android project (generated by Capacitor)
├── capacitor.config.ts      # app id + name + web dir
└── package.json
```

The only line I changed from your web version is in `www/js/api.js`:
```js
const API_BASE = "https://your-backend.onrender.com/api";
```
**Replace this with your actual deployed backend URL before building.** A phone
can't reach `localhost:8080` — that only worked because your browser and Flask
server were on the same machine. The backend itself needs zero changes; it's
already a REST API serving any client.

---

## 2. One-time setup on your machine

You need:
- **Node.js** (v18+) — https://nodejs.org
- **Android Studio** — https://developer.android.com/studio (installs the Android
  SDK for you; open it once after install so it finishes the SDK setup wizard)

```bash
cd inventory-mobile-app
npm install
```

---

## 3. Point it at your real backend

Edit `www/js/api.js`, set `API_BASE` to your deployed Render URL, then re-copy
the change into the native project:

```bash
npx cap sync android
```

Run this `sync` command any time you edit anything in `www/` — it copies your web
files into the native Android project.

---

## 4. Build and run

**Easiest: open in Android Studio and run on an emulator or your phone**
```bash
npx cap open android
```
This opens the `android/` folder in Android Studio. Click the green ▶ Run button,
pick a device (emulator or your phone via USB with USB debugging on), and it
installs and launches like a normal app.

**Or from the command line, build an installable APK directly:**
```bash
cd android
./gradlew assembleDebug
```
The APK lands at:
```
android/app/build/outputs/apk/debug/app-debug.apk
```
Copy that file to your phone (or `adb install app-debug.apk` with the phone
connected) and install it — Android will ask you to allow installs from this
source the first time.

---

## 5. iOS (optional, needs a Mac)

Capacitor supports iOS the same way, but building it requires Xcode, which only
runs on macOS. If you have access to a Mac:
```bash
npm install @capacitor/ios
npx cap add ios
npx cap open ios
```
Then build/run from Xcode directly. Same `www/` folder, same API calls — nothing
else changes.

---

## 6. Why this counts as "the mobile version" for your submission

- Same deployed backend, same cloud database, same REST APIs — no duplicate work.
- The app is a real installable `.apk`, not just a bookmarked website — it has its
  own icon, launches standalone, and runs in a WebView, not a browser tab.
- If asked in a viva why this approach: it demonstrates that a well-designed REST
  API is client-agnostic — the same backend serves a web frontend and a mobile
  app without modification, which is itself a legitimate point about good API
  design worth mentioning.

## 7. If you want a more "native" app later

This WebView approach is genuinely fine for a student project. If you ever want
truly native navigation, offline support, or push notifications, the next step
up is rewriting just the `www/` UI layer in React Native or Flutter, still hitting
the same `/api/...` endpoints. That's a separate, bigger effort — not needed here.
